Wildcard-Masken-Rechner: So funktioniert er

Cisco-Access-Listen sowie network-Anweisungen von OSPF und EIGRP erwarten statt einer Subnetzmaske eine Wildcard-Maske. Ein 0-Bit bedeutet „muss übereinstimmen“, ein 1-Bit „ignorieren“ – die Wildcard ist also einfach die bitweise Umkehrung der Subnetzmaske: 255.255.255.255 minus die Maske, Oktett für Oktett.

SubnetKit zeigt bei jeder Berechnung die Wildcard neben der Subnetzmaske, und die freie Eingabe akzeptiert die Syntax address wildcard direkt aus einer IOS-Konfiguration. Das Tool ist kostenlos und läuft im Browser.

Durchgerechnetes Beispiel: 172.16.32.0/20

  • Subnetzmaske: 255.255.240.0
  • Wildcard-Maske: 0.0.15.255 (255 − 255 = 0, 255 − 255 = 0, 255 − 240 = 15, 255 − 0 = 255)
  • Abgedeckter Adressbereich: 172.16.32.0 – 172.16.47.255 (4.096 Adressen)

Derselbe Block in IOS-Syntax:

  • access-list 10 permit 172.16.32.0 0.0.15.255
  • router ospf 1 dann network 172.16.32.0 0.0.15.255 area 0

Um einen einzelnen Host abzugleichen, nutze die Wildcard 0.0.0.0 oder das Schlüsselwort host; um alles abzugleichen, nutze 0.0.0.0 255.255.255.255 oder any. Füge 172.16.32.0 0.0.15.255 in das Schnelleingabefeld von SubnetKit ein, und es wird automatisch als /20 erkannt.

Referenz: Präfix, Maske und Wildcard

  • /8 255.0.0.0 → 0.255.255.255
  • /16 255.255.0.0 → 0.0.255.255
  • /20 255.255.240.0 → 0.0.15.255
  • /24 255.255.255.0 → 0.0.0.255
  • /25 255.255.255.128 → 0.0.0.127
  • /26 255.255.255.192 → 0.0.0.63
  • /27 255.255.255.224 → 0.0.0.31
  • /28 255.255.255.240 → 0.0.0.15
  • /30 255.255.255.252 → 0.0.0.3
  • /32 255.255.255.255 → 0.0.0.0

Wildcards sind nicht auf zusammenhängende Einsen beschränkt. In einer ACL würde 0.0.1.0 auf jedes gerade oder ungerade dritte Oktett passen – ein Trick, der gelegentlich genutzt wird, um abwechselnde Subnetze in einer Zeile abzugleichen. Solche nicht zusammenhängenden Masken sind in ACLs erlaubt, aber nicht in OSPF.

Häufig gestellte Fragen

Wie berechne ich eine Wildcard-Maske?

Ziehe jedes Oktett der Subnetzmaske von 255 ab. Für 255.255.255.192 ergibt das 0.0.0.63.

Ist eine Wildcard-Maske dasselbe wie eine inverse Maske?

Ja. Die Cisco-Dokumentation verwendet beide Begriffe für das bitweise Komplement der Subnetzmaske.

Warum nutzt OSPF Wildcard-Masken?

Die network-Anweisung hat ursprünglich die Abgleichslogik von ACLs wiederverwendet, die Adressbits selektiv prüft. Modernes IOS akzeptiert hier auch eine Subnetzmaske und wandelt sie um, aber Prüfungen erwarten weiterhin die Wildcard-Form.

Welche Wildcard passt auf einen einzelnen Host?

0.0.0.0, das heißt, jedes Bit muss übereinstimmen. In ACLs kannst du host 10.1.1.5 statt 10.1.1.5 0.0.0.0 schreiben.
