IP-Bereich-zu-CIDR-Konverter: So funktioniert er

Firewalls, Cloud-Sicherheitsgruppen und Routing-Tabellen wollen CIDR-Notation, aber Hersteller, Provider und Tabellen liefern oft einen Bereich wie 192.168.1.100 bis 192.168.1.199. Sofern der Bereich nicht zufällig ein an einer ausgerichteten Grenze beginnender Zweierpotenz-Block ist, braucht es mehrere CIDRs, um ihn exakt auszudrücken.

Der CIDR-Tab von SubnetKit berechnet die minimale Liste kostenlos im Browser und kann auch umgekehrt: jedes CIDR in seine erste und letzte Adresse auflösen.

Durchgerechnetes Beispiel: 192.168.1.100 – 192.168.1.199

100 Adressen, an keinem einzelnen Block ausgerichtet, daher erzeugt der Konverter fünf CIDRs:

  1. 192.168.1.100/30 → .100–.103 (4 Adressen)
  2. 192.168.1.104/29 → .104–.111 (8)
  3. 192.168.1.112/28 → .112–.127 (16)
  4. 192.168.1.128/26 → .128–.191 (64)
  5. 192.168.1.192/29 → .192–.199 (8)

4 + 8 + 16 + 64 + 8 = 100, ohne eine Adresse außerhalb der Anfrage. Der Algorithmus läuft von der Startadresse aus und wählt jedes Mal den größten Block, der sowohl an einer ausgerichteten Grenze beginnt (ein /29 muss bei einem Vielfachen von 8 beginnen, ein /26 bei einem Vielfachen von 64) als auch nicht über die Endadresse hinausgeht.

Bereiche, die zu einem einzigen CIDR zusammenfallen

Manche Bereiche sind bereits saubere Blöcke, und das Tool gibt nur eine Zeile aus:

  • 192.168.1.0 – 192.168.1.255 → 192.168.1.0/24
  • 10.0.0.0 – 10.0.1.255 → 10.0.0.0/23 (512 Adressen)
  • 172.16.0.0 – 172.31.255.255 → 172.16.0.0/12

Ein häufiger Fehler ist, beim Angeben des Bereichs Netzwerk und Broadcast auszulassen. 10.0.0.1 – 10.0.0.254 ist kein /24; dafür braucht es 14 CIDRs (10.0.0.1/32, 10.0.0.2/31, 10.0.0.4/30 … 10.0.0.254/32). Wenn du das ganze Subnetz meinst, gib .0 bis .255 ein. SubnetKit enthält außerdem eine Zugehörigkeitsprüfung, mit der du bestätigen kannst, dass eine einzelne Adresse wie 192.168.1.150 in dem CIDR liegt, das du gerade in eine Regel eintragen willst.

Häufig gestellte Fragen

Warum wird mein Bereich zu mehreren CIDR-Blöcken?

CIDR-Blöcke müssen eine Zweierpotenz groß sein und an einer Grenze beginnen, die durch diese Größe teilbar ist. Ein nicht ausgerichteter Bereich muss durch mehrere kleinere Blöcke abgedeckt werden.

Wie rechne ich ein CIDR zurück in einen Bereich um?

Gib das CIDR im Feld CIDR zu Bereich ein; SubnetKit zeigt erste und letzte Adresse, Gesamtzahl und Maske.

Kann ich prüfen, ob eine IP in einem CIDR liegt?

Ja. Der CIDR-Tab enthält eine Prüfung, die dir sagt, ob eine Adresse zu einem bestimmten Block gehört, zum Beispiel ob 192.168.1.150 in 192.168.1.128/26 liegt.

Gibt es eine Begrenzung der Bereichsgröße?

Nein. Jeder IPv4-Bereich von einer einzelnen Adresse bis 0.0.0.0–255.255.255.255 wird unterstützt, und die Ergebnisse werden sofort im Browser berechnet.
